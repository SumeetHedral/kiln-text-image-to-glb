# kiln-text-image-to-glb

A Claude Code workflow that turns a text brief and/or reference image into a reviewed GLB using [Kiln](https://github.com/instruktlabs/kiln), plus a static gallery that shows the results.

**Live gallery:** https://sumeethedral.github.io/kiln-text-image-to-glb/

## How it works

Kiln runs locally through your coding agent (MCP/CLI), so generation is not hosted. The skill [`kiln-text-image-to-glb`](.claude/skills/kiln-text-image-to-glb/SKILL.md) chains Kiln's own author, refine and QA skills:

1. Intake: read the image or brief, write a short spec (parts, scale, materials, what the image cannot show).
2. Author a procedural Kiln program and render a six-view sheet.
3. Compare against the reference, then refine with anchored edits (max 3 rounds).
4. QA, then deliver `asset.glb`, `asset.kiln.js`, the contact sheet and a report.

A reference image guides silhouette, proportions and materials. It does not recover hidden sides or exact geometry.

## Set up

Needs Node 20.15+ or 22.2+.

```bash
scripts/setup.sh ~/kiln-workspace
cd ~/kiln-workspace && claude
```

This installs `@instruktlabs/kiln` (outside the workspace), creates a Claude Code workspace with `kiln-init --harness claude`, and copies this skill in. Accept the project and MCP trust prompts, then ask:

> Use kiln-text-image-to-glb on ./photo.jpg

## Live site features

- **Text to 3D, in your browser.** Type a prompt: SD-Turbo (ONNX Runtime Web, WebGPU) makes an image in one denoising step, then Depth Anything V2 turns it into a displaced relief mesh you can orbit and export as GLB. Needs WebGPU with `shader-f16` and a one-time ~2.5 GB model download (cached by the browser). The weights come straight from Hugging Face, so nothing large lives in this repo. SD-Turbo is under Stability AI's license: check it fits your use before relying on this commercially.
- **Image to 3D.** Drop or paste any image for the same relief pipeline.
- **Kiln assets.** Browse the GLBs generated by the Kiln workflow above.
- **WebGL / WebGPU comparison.** Live overlay with FPS, frame time and p95, CPU submit time, GPU time (timer queries where the browser allows), triangles, draw calls, geometry/texture counts, and LOD levels in use. Controls: Copies (1 to 1000), Wireframe, and for generated reliefs Density (60 to 960), Auto-LOD (three.js `LOD`), Depth, Cut background and Smooth. **Benchmark** runs WebGL2 then WebGPU back to back and tabulates both. FPS is capped at the display refresh rate, so compare CPU and GPU milliseconds.

**Solid (closed back).** Tick it on a generated relief to get a watertight mesh instead of a paper-thin sheet. The page mirrors the front shell into a back shell, with thickness set by the Thickness slider plus the depth, and stitches wall triangles along every open edge. Raise Cut background first to isolate the object. The back is inferred by mirroring, so it fits symmetric objects like a teapot and is a guess for anything else. Real multi-view generation (Zero123++, MV-Adapter and similar) would need a GPU server, since no in-browser port exists yet.

A relief is otherwise a front-facing displaced surface: hidden sides are not modelled. Kiln assets are full procedural objects.

## Publish a result to the gallery

```bash
node scripts/add-asset.mjs camping-lantern "Camping lantern" "Brief shown on the page" asset.glb sheet.png asset.kiln.js
git add site && git commit -m "Add asset" && git push
```

Pushing to `main` redeploys `site/` to GitHub Pages. The viewer uses three.js with a WebGL / WebGPU toggle and live frame stats.
